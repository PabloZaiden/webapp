# Release and publishing

## Pull requests

`PR Checks` runs on every pull request:

1. Install dependencies with `bun install --frozen-lockfile`.
2. Run `bun run typecheck`.
3. Run `bun run test:build-binary`.
4. Run `bun run test:remaining`.
5. Build both example apps with `bun run build:examples`.
6. Start the compiled example binaries and smoke-test `/api/health` plus one public app endpoint.

## Main branch

`Main Docker Smoke` runs on pushes to `main`:

1. Install dependencies and run `bun run typecheck`.
2. Build Linux x64 and Linux arm64 binaries for both examples.
3. Build each Docker image with an explicit `linux/amd64` or `linux/arm64` platform and matching `APP_BINARY` path.
4. Validate missing, unsupported, and mismatched Docker arguments fail during the image build.
5. Run both architecture variants of both containers.
6. Smoke-test `/api/health` plus one public app endpoint through the published container ports.

## GitHub distribution

The framework is distributed directly from GitHub, not npm:

```bash
bun add github:PabloZaiden/webapp#<commit-or-tag>
```

Commit-pinned dependencies are supported for both development and final
integrations. Update dependency manifests and lockfiles together; an
intermediate release is not required for cross-repository work.

### Creating a GitHub release

Install [GitHub CLI](https://cli.github.com/) and authenticate with
`gh auth login` using an account allowed to create releases in the repository.
From the repository, run:

```bash
bun run release
```

The script uses the highest published stable `vX.Y.Z` release on GitHub as
the baseline, ignoring drafts, prereleases, and tags in other formats. It
requires an existing stable release; local tags and the development version in
`package.json` are not used.

Choose `major`, `minor`, or `patch`. Major resets minor and patch to zero;
minor resets patch to zero. The script previews the proposed tag/title and
the remote default branch's commit SHA. It releases that exact remote commit,
regardless of your current local branch or unpushed changes.

Only typing `yes` at the final prompt publishes. Enter at the bump prompt,
EOF, or any other confirmation cancels without creating a tag or release.
The tag and title are always the same `vX.Y.Z` string, and the description
is generated by GitHub. Existing remote tags are rejected. Do not publish a
real release merely to validate the script.

GitHub tags provide optional named snapshots. No npm publication step or npm
credentials are required.
